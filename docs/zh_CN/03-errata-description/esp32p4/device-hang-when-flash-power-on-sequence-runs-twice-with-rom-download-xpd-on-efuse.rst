[ROM-816] ``rom_download_xpd_on`` 启用后 flash 上电流程重复执行导致卡死
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. only:: esp32p4

   .. tags::

      v3.2

描述
^^^^

为修复在 ESP32-P4 芯片版本 v3.1 及更早版本的安全下载模式下，无法通过 esptool 为 flash 上电的问题，ESP32-P4 芯片版本 v3.2 中新增了 eFuse ``rom_download_xpd_on``。当该 eFuse 位被烧写后，ROM 会在下载流程中自动执行 flash 上电相关代码。

该上电代码在同一次上电复位 (POR) 周期内不能执行两次，否则流程无法正常退出，芯片会出现卡死。

可能触发“执行两次”的情况包括：

- eFuse 中已烧写 ``rom_download_xpd_on``，但主机侧仍向芯片发送 flash 上电序列。若使用已修复的 esptool，在非安全下载模式下会先检查该 eFuse 位，仅在未烧写时才会自动发送上电序列，因此一般不会出现此组合。
- 在安全下载模式下，通过 USB UART 接口烧写 ``rom_download_xpd_on`` 后，再使用 USB UART 的强制下载去烧录固件。由于 USB UART 触发的复位通常不是完整上电复位，复位后再次进入下载相当于在同一上电周期内再次执行了 flash 上电相关代码，从而触发上述卡死风险。

变通方法
^^^^^^^^

- 仅在确实需要启用安全下载模式时，再去烧写 ``rom_download_xpd_on`` 位。
- 若使用 USB UART 接口进行固件下载，在烧写该 eFuse 位之后，下载固件前应先对芯片执行一次完整上电复位，再进入下载流程。

解决方案
^^^^^^^^
